# 01. 프로젝트 컨텍스트

## 1. 배경

Duomo&Co 조명플래그십파트는 Flos, Artemide, B&B, Poltrona Frau, Knoll, Maxalto, Cassina, Ceccotti 등 다수 수입 브랜드의 발주·통관·입고·출고를 관리함. 발주 후 입항까지 30~120일이 소요되며, **입고 시점에 출고 처리가 지연되면 매출·고객만족도에 직접 영향**.

기존에는 lilychoi님이 진행일지를 수동 업데이트하여 카톡·구두로 공유했으나:
- 4인 팀(서영완·조이경·추승민·윤소담)이 자기 담당 건을 놓치는 경우 발생
- 입항 임박 사전 준비가 누락되어 통관 후 대기 시간 증가
- 출고 처리 지연으로 고객 컴플레인

→ **OWNER / 플래그십 대쉬보드의 4번째 모듈로 자동 알람 시스템 추가**

## 2. 핵심 워크플로우

```
[Source 1: 재고 발주 엑셀 - 수동 업로드]
        ↓
   "내 이름/팀원 이름이 있는가?"
   → 선점된 발주건 식별
        ↓
[Source 2: Google Drive 진행일지 - 실시간]
        ↓
   "입고 일정이 어떻게 되는가?"
   → 입항예정일/입고완료 더블체크
        ↓
[Output: Slack #조명플래그쉽파트]
   → 4인별 개별 @멘션 알람

[Storage: Notion 발송이력 DB]
   → 중복 발송 방지
```

### 알람 2단계 체계

| 단계 | 트리거 | 목적 | 메시지 |
|---|---|---|---|
| 1차 | 입항예정 **D-14** | 사전 통관·납품 준비 | 🚢 입항 임박 |
| 2차 | **입고완료** 신규 감지 | 즉시 출고 처리 | 📦 입고 완료 |

## 4. 알람 발송 사양

### Slack 채널
- `#조명플래그쉽파트` (기존 채널)
- Bot Token 발급 필요 (`xoxb-...`)
- 채널 ID는 Streamlit Secrets에 저장

### 메시지 템플릿

**1차 알람 (입항임박 D-14)**
```
🚢 [입항 임박 D-{N}] {ETA}

@{담당자} 입항예정 건입니다. 출고 일정 확정 부탁드립니다.

■ PO No.: {PO_NO}
■ Brand: {SUPPLIER}
■ Project: {PROJECT}
■ 운송: {SHIPPING_MODE}
■ 도착예정: {ETA}
■ 품목: {DESCRIPTION} (수량 {QTY})
```

**2차 알람 (입고완료)**
```
📦 [입고 완료] {입고일자}

@{담당자} 출고 처리 필요 건입니다.

■ PO No.: {PO_NO}
■ Brand: {SUPPLIER}
■ Project: {PROJECT}
■ 입고일: {입고일자}
■ 품목: {DESCRIPTION} (수량 {QTY})
```

## 5. 시스템 실행 흐름

```
[매일 정해진 시간 - 또는 수동 트리거]

STEP 1. Source 2 로드 (Drive 진행일지)  ← 메인 데이터 소스
  - MCP download_file_content 또는 Drive API
  - 모든 시트 통합 → DataFrame
  - E열 '영업부 담당자'로 4인 필터링
  - → [진행 중 발주건 리스트]

STEP 2. Source 1 로드 (재고 엑셀, 선택)
  - 업로드된 최신 파일 파싱
  - 4인 이름이 등장하는 PO 블록 추출
  - → [선점된 발주건 리스트]
  ※ Source 1은 보조 검증용. Source 2만으로도 알람 발송 가능.

STEP 3. 교차 매칭 (선택)
  - PO No. 또는 Project 기준
  - 매칭된 건 = 우리 팀 선점 + 일정 추적 대상
  - 미매칭 건 = '확인 필요' 리스트로 분리

STEP 4. 알람 조건 판정
  - 1차: ETA - 오늘 ≤ 14일 AND 입고 컬럼 비어있음
  - 2차: 입고 컬럼에 신규 날짜 입력 감지 (전회 스캔과 비교)
  - Notion 발송이력 DB 조회로 중복 제외

STEP 5. Slack 발송
  - 담당자별 개별 @멘션
  - 발송 후 Notion 이력 DB 업데이트
```
